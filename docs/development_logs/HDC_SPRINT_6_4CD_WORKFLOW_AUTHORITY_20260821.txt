HDC Sprint 6.4C/D - Workflow Backend Authority
Date: 2026-08-21

Outcome
-------
Prepared the provider-neutral HDC API and PostgreSQL migration for real service
requests, proposals, proposal acceptance, transaction handoffs, and service
transaction status. The production database and production Netlify deployment
were not changed during preparation.

Backend work
------------
- Added migrations/0002_workflow_authority.sql.
- Added authenticated workflow bootstrap and mutation routes.
- Added PostgreSQL row-level security executed through the restricted hdc_app
  role with transaction-local authenticated identity and roles.
- Kept customer/technician IDs, names, proposal reputation, quality scores,
  offer counts, timestamps, transaction activities, and relationships under
  server authority.
- Made proposal acceptance atomic: one proposal is accepted, competing active
  proposals are declined, the request is locked, and a consumed handoff plus
  confirmed transaction workspace are created in the same DB transaction.
- Used request-before-proposal locking for mutations that can update proposal
  offer counts, preventing conflicting lock order during concurrent acceptance.
- Request cancellation expires draft proposals and declines active proposals in
  the same database transaction so cancelled work cannot retain live offers.
- Added participant- and status-specific transaction transitions which also
  update the linked service-request status atomically.
