HDC SPRINT 5.4D DEVELOPMENT LOG
=================================
Sprint: 5.4D - Professional Proposal Comparison
Date: 2026-08-20

PURPOSE
-------
Give customers a transparent way to compare two or three professional
technology-service proposals before any acceptance/transaction action exists.

ARCHITECTURE REVIEW
-------------------
Approved because proposal comparison directly supports HDC's technology-service
marketplace and customer decision-support mission.

Backend/domain-first order used:
1. ProposalComparison domain model.
2. ProposalComparisonService rules and deterministic calculations.
3. ProposalProvider comparison bridge.
4. Customer Proposal Inbox selection UI.
5. Professional Proposal Comparison UI.

IMPORTANT DESIGN DECISION
-------------------------
HDC does NOT calculate or declare an overall "best technician" or "best
proposal". The engine only highlights objective category leaders. Nexus
explains trade-offs and explicitly leaves the decision to the customer.

DATA INTEGRITY RULES
--------------------
- Minimum 2 and maximum 3 proposals.
- Every proposal must belong to the same ServiceRequest.
- Duplicate proposal IDs are rejected.
- Only submitted/viewed/shortlisted proposals are eligible.
- Comparison does not mutate proposal status.
- Comparison data remains derived from the existing Proposal source of truth.

TRUTHFUL-DATA CORRECTION
------------------------
The current TechnicianReputationSnapshot contains memberSinceYear but does not
contain verified years of professional experience. Therefore Sprint 5.4D uses
"HDC tenure" rather than presenting membership tenure as professional
experience. A true experience metric can be added later when the technician
profile/backend owns verified experience data.
